# CallRewrite — долг после этапа 4

Статус: **pending** (не в pipeline черновика).

## Почему не в этом срезе

Для безопасного CallRewrite нужны одновременно:

- лексический разбор вызовов в теле (не подстрочная замена имён);
- доказанный граф вызовов **внутри одного** общего модуля;
- согласованность с контрактом (`КонтрактМетода`) и отсутствие динамики (`ДиагностикаВызовов`);
- отдельный артефакт output до удаления/замены типового метода в `restored`.

Текущий анализатор даёт контракты и блокировку `Выполнить`/`Вычислить`, но **не** разбирает идентификаторы вызовов по AST. Реализация «одного сценария» без этого — либо ложная уверенность, либо риск порчи строк/комментариев.

## Уже есть

- `callRewritePreview` в отчёте (диагностика, не факт переписывания).
- Авто-перенос блокируется при несовпадении сигнатур и динамических вызовах.

## Следующий шаг (когда будет этап 4b)

Один контролируемый модуль-фикстура, sidecar `extension/callrewrite/`, unit + интеграционный тест на output; межмодульные/экспортные/неоднозначные вызовы — `manual` с причиной.
