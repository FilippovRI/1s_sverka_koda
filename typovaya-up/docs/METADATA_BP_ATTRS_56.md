## Реализация в генераторе (25.11.2026)

`ДобавлениеМетаданныхБп`: если тип реквизита/ТЧ отсутствует в restored, объект типа копируется из XML БП (только файл метаданных, без форм и модулей) и регистрируется в Configuration.xml; зависимости типов разбираются транзитивно (перечисления, определяемые типы, справочники).

План счетов Хозрасчетный **не переносится**: в typovaya нет ни одного плана счетов; у него ExtDimensionTypes = ВидыСубконтоХозрасчетные, формы; наивное замыкание по всему XML уходит за 500 объектов, в т.ч. десятки регистров накопления. Реквизит БанковскиеСчета.СчетБанк остаётся в todo.

Документы и регистры сверх необходимого не переносятся. Тест: typovaya-up/tests/test_metadata_bp_added.os (перечисление только БП появляется в restored и Configuration.xml, реквизит добавляется; Хозрасчетный не копируется).

## Коллизия UUID InternalInfo (пакет meta56)

`DefinedType.ТерриторияВыполненияРаботВОрганизации` (БП) и `DefinedType.ТерриторииВыполненияРаботВОрганизации` (typovaya) — один объект: одинаковые uuid, TypeId `a22d096d-429d-42ab-959d-59213ea31ca0` и ValueId. Генератор не копирует такой тип, а подменяет ссылку в реквизите/ТЧ на имя typovaya. Первая загрузка без этой проверки падала на ibcmd import (`Тип порождаемый объектом InternalInfo содержит не уникальное значение`).

Копируемый объект типа записывается без форм и макетов: из XML удаляются узлы `Form`/`Template` и значения `Default*Form`/`Auxiliary*Form`/`ChoiceForm`, если файла формы нет в restored, иначе ibcmd import требует отсутствующие `Forms/*.xml` и `Templates/*.xml`.
