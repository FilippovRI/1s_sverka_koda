Дата актуализации: 2026-11-07. Методика оценки сложности: `tests/measure_complexity.py` (эвристика **typovaya-up cognitive load**, не Sonar).

## Этап 1 — качество кода, документация, XML (текущий)

| ID | Задача | Приоритет | Критерии приёмки | Статус |
|----|--------|-----------|------------------|--------|
| 1.1 | Поэтапный план + поток данных | P0 | `docs/PLAN.md`, `docs/FLOW.md` в репозитории | **Готово** |
| 1.2 | Рефакторинг `Записать`, `СравнитьМодуль` без смены поведения | P0 | `run_tests.sh` зелёный; суммарная эвристика сложности ↓ vs baseline | **Готово** (см. `docs/complexity_*.json`) |
| 1.3 | Технические комментарии к публичным API | P1 | Назначение/параметры/побочные эффекты у ключевых `Экспорт` | **Частично** (ядро черновика и сравнения) |
| 1.4 | XML: InternalInfo/ChildObjects для ibcmd 8.5+ | P0 | Нет пустых `ChildObjects` у CommonModule/Language; InternalInfo копируется из УП; Configuration из `extension_meta/` | **Готово на фикстурах** |

**Риски этапа 1:** эвристика сложности не равна Sonar; ibcmd на Linux в CI не гоняется — только unit/integration на фикстурах.

## Ограничения (инварианты)

- Исходные `D:\Выгрузка УП` / `D:\выгрузка БП` не трогаем; выгрузки и отчёты не коммитим.
- Утилита — sibling `Sverka.*`, без смешивания архитектур.
- Агент не запускает ibcmd против пользовательских баз.
