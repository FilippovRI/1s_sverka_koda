# Класс 3: метаданные БП, на которые ссылается код (добавление в restored)

Решение 24.11 (t744u) частично снимает правило «класс 3 не добавляем».

## Правило

Класс 3 — реквизиты, табличные части, колонки ТЧ и значения перечислений, которые есть в БП и отсутствуют в УП.

- **Есть ссылка из кода restored** — элемент добавляется в XML объекта **restored** (выход генератора). Фрагмент XML берётся из выгрузки БП как есть, с UUID БП.
- **Нет ссылок из кода** — не добавляется, остаётся в `todo_missing_metadata`.
- Исходные выгрузки (УП, БП) только читаются.

Шаг: `src/ДобавлениеМетаданныхБп.os`. В `Главный.os` он идёт перед `TodoMissingMetadata`. Добавленное в `todo_missing_metadata` не попадает. Отдельный запуск на готовом выходе: `oscript scripts/run_metadata_bp.os <out> [выгрузка БП]`. Тест: `tests/test_metadata_bp_added.os`.

### Что считается ссылкой из кода

- реквизит, ТЧ, колонка ТЧ: имя встречается как слово в модулях самого объекта (модуль объекта, менеджера, набора записей, форм); комментарии не считаются. Ошибки компиляции «Переменная не определена» дают как раз эти модули;
- значение перечисления: `Перечисления.Имя.Значение` / `Перечисление.Имя.Значение` в любом модуле restored или имя в модулях самого перечисления.

Обращения из чужих модулей (`Объект.Реквизит` в запросах и через переменные) не ищутся: на полной выгрузке такой поиск идёт больше 20 минут. Такие элементы остаются в todo.

### Когда элемент не добавляется (todo, причина в `metadata_bp_added.csv`)

- нет ссылок из кода;
- тип или иная ссылка во фрагменте XML (`cfg:…Ref.X`, `DefinedType.X`, `Enum.X.EnumValue.Y`, `….Attribute.Y` и т.п.) ведёт на объект или подчинённый элемент, которого нет в restored;
- UUID фрагмента уже есть в XML объекта restored;
- фрагмент не найден в XML БП или нет места вставки.

Порядок вставки: реквизит — после последнего реквизита объекта; ТЧ — после последней ТЧ (или реквизита); колонка — в ChildObjects своей ТЧ; значение перечисления — в конец. Повторный запуск ничего не меняет.
