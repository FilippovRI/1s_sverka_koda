# Сверка

Настольная программа для Windows, которая сравнивает две выгрузки конфигурации 1С (до и после обновления) и показывает, где изменения типового кода задевают ваши расширения. Базу данных программа не открывает и ничего в ней не меняет — работает только с файловыми выгрузками из Конфигуратора.

## Что делает

- **Сравнение конфигураций.** Показывает полный список отличий между двумя выгрузками: добавленные, удалённые, переименованные объекты, изменения свойств, состава и текста модулей. Сравнение идёт на уровне отдельных методов, а не файлов целиком; комментарии и пустые строки отличием не считаются. Объекты сопоставляются по `uuid`, поэтому переименование не выглядит как «удалил и добавил».
- **Анализ влияния на расширения.** Если указать папку с расширениями, программа отдельно отметит места, до которых расширение дотягивается: перехваты процедур (`&Перед`, `&После`, `&Вместо`, `&ИзменениеИКонтроль`), вставки и удаления кода, вызовы общих модулей и заимствованные реквизиты. Каждой находке присваивается уровень риска.
- **Сводка по расширениям.** При пакетной работе с несколькими расширениями показывает таблицу с числом находок каждого уровня по каждому расширению, чтобы понимать, куда смотреть первым.
- **Отчёты.** Сохраняет результат в HTML (для чтения) и JSON (для передачи дальше).
- **История.** Сравнивает два сохранённых прогона и показывает, что появилось нового, что уже снято и что осталось неразобранным.

## Уровни риска

- **Критично** — метод или реквизит, на который опирается расширение, удалён, либо у перехваченного метода изменились параметры. Исправить до работы пользователей.
- **Адаптация** — расширение вставляет свой код внутрь процедуры, и обновление изменило именно те строки, рядом с которыми стоит вставка. Проверить вручную в первую очередь.
- **Предупреждение** — расширение работает после изменившегося метода, продолжает его вызов, использует изменившийся реквизит или вставка уцелела, но тело процедуры изменилось в стороне от неё. Компиляция обычно сохраняется, но смысл типового кода мог сдвинуться.
- **Не проверено** — в модуле расширения есть `Выполнить` или `Вычислить`; программа не может определить, что именно так запускается, и лишь напоминает заглянуть в модуль.

## Как пользоваться

1. **Подготовьте выгрузки в Конфигураторе.** Для версии до обновления: `Конфигурация → Выгрузить конфигурацию в файлы` в пустую папку (должен появиться `Configuration.xml`). То же для версии после обновления — в отдельную пустую папку. Расширения выгружаются так же; несколько расширений можно положить соседними папками внутри одной общей.
2. **Укажите папки в окне.** «Выгрузка ДО», «Выгрузка ПОСЛЕ» и, при необходимости, «Расширения» (можно оставить пустым — тогда будет только список изменений конфигурации). Нажмите «Сверить».
3. **Разберите результат** на вкладках «Конфигурация» и «Расширения». Щелчок по строке метода показывает его текст «Было»/«Стало».
4. **Сохраните отчёт** при необходимости и позже сравните прогоны на вкладке «История».

Подробная инструкция встроена в программу — вкладка «Инструкция».

## Установка

Скачайте `sverka.exe` из раздела [Releases](https://github.com/FilippovRI/1s_sverka_koda/releases) и запустите. Это самодостаточный единый файл для Windows x64, установка и .NET на машине не требуются.

## Сборка из исходников

Нужен [.NET SDK 8](https://dotnet.microsoft.com/download/dotnet/8.0).

```powershell
# запуск из исходников
dotnet run --project src/Sverka.App/Sverka.App.csproj

# тесты
dotnet test

# сборка единого exe
dotnet publish src/Sverka.App/Sverka.App.csproj -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o publish
```

## Структура проекта

- `src/Sverka.Core` — ядро: чтение выгрузок, сравнение по методам, анализ влияния, отчёты. Детерминированное: одинаковый вход даёт одинаковый JSON.
- `src/Sverka.App` — оконный интерфейс на Avalonia.
- `tests/Sverka.Core.Tests` — тесты ядра.
